# Claude Code Action Guide: COMPAS IFC Appendix Outputs

## Goal

Run all 11 COMPAS IFC evaluation scripts and produce **condensed outputs** suitable for printing in Appendix A of a PhD thesis. Each output should be ~20-40 lines max, not hundreds. The condensed outputs will be collected into a single file `appendix_a_outputs.txt`.

## Context

- The thesis body text already contains abbreviated code snippets showing the testing logic.
- The appendix needs to show the **evidence** (results), not the code.
- Per-element repetitive PASS lines must be collapsed into aggregate counts.
- The current raw outputs are far too long (e.g., the Duplex roundtrip produces 274 individual PASS lines).

## Environment Setup

The scripts assume:
- `compas_ifc` is installed with OCC support
- Test data files are in `data/` (Duplex IFC, HiLo IFC)
- BRep STEP files exist (generated by a prerequisite script)
- A `temp/` directory exists for intermediate outputs

Make sure dependencies are available before running. If any test data is missing, note it in the output rather than failing silently.

---

## Strategy

There are two approaches. Pick whichever is more practical:

**Option A (preferred): Run each script, capture raw stdout, then post-process into condensed format.**

Each script already prints structured output with clear section headers (`=====`) and a SUMMARY block at the end. Write a post-processing step that extracts:
1. The header/config section (model name, element counts)
2. Any distribution tables (type counts, rectification patterns)
3. The final summary line (`X PASS / Y FAIL`)
4. Collapse all individual per-element PASS/FAIL lines into counts per category

**Option B: Modify each script to add a `--condensed` flag that produces short output.**

This is cleaner but requires editing 11 files. Only do this if Option A proves too messy.

## Important Notes

1. **Do not invent numbers.** Every value in the condensed output must come from the actual script output. If a script fails or a number differs from what the thesis body text claims, flag it.

2. **The target formats above are templates, not exact.** Adapt to what each script actually prints. The key constraint is: **no individual per-element PASS lines in the final output.** Aggregate them.

3. **If a script fails to run** (missing data, import error), document the error and move on. We can address it separately.

4. **Version numbers matter.** Record the exact versions of compas_ifc, Python, IfcOpenShell, and OpenCascade at the top of the output file.

5. **Total check count.** The thesis claims "897 individual checks with zero failures" in §4.6.6. Verify this by summing the PASS counts across all scripts. If it differs, flag it.
